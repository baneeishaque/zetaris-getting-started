How the request works

The app sends SQL to Zetaris at /sql-editor/sqls/run with the API key in the Authorization header. It queries the series view for observations and the metadata view for the dataset label, source, and update timestamp.

  • The API key is held in memory and sessionStorage for this tab only.
  • Saved series remain in localStorage; they contain filters and notes, never the API key.
  • The dev proxy is required locally because Zetaris does not send CORS headers. A production deployment needs a same-origin reverse proxy.
  • This is a local demonstration, not a pattern for publishing a Zetaris key in a public app.
